# 0010. CLI: Typer

- Status: Accepted
- Date: 2026-10-20

## Context

Conveyor is driven from the command line first (`conveyor validate`, later `conveyor agent
publish` and running factories). The CLI should be typed, documented from the code, consistent
about exit codes and easy to test without subprocesses.

## Decision

Use **Typer**, exposed as the `conveyor` console script (`conveyor.cli:app`). Commands are thin:
they call library functions and format results. Exit codes follow Click's convention: `0`
success, `1` the command ran and found problems, `2` usage errors (bad arguments, missing or
unusable paths). Problems are printed as plain `file:line:column: field: message` lines, one per
problem, so editors and CI can parse them. Tests use Typer's `CliRunner`.

## Alternatives considered

- **Click** — Typer is built on Click and adds type-hint-driven parameters with less code.
- **argparse** — no dependency, but more boilerplate, weaker help output and no test runner.

## Consequences

Typer brings Rich and Shellingham as transitive dependencies. Help and usage errors are
rendered by Rich; command output stays plain text for stability.
